spacemacs-u24: dev notes

13 November 2026. Spacemacs as one self-contained folder on Ubuntu 24.04, built on the Tokyo box, running there in a container for you to try, and tested inside the verl image. This page says what was asked, where the line between the two Dockerfiles is, what was built, how it was checked, and where every file and log is.

Try it

tokyo            # on the Mac: opens the SSM session to the Tokyo box
smx emacs        # Emacs in the stand-alone container, in /work
smx              # or a shell there; then type: emacs

Inside the verl image (same editor, verl's own Python and uv):

sudo docker run --rm -it --entrypoint bash -v /opt/spacemacs-dev/repos:/work verl-spacemacs:latest
emacs            # add --gpus all to the docker run line when you need the GPUs
  • Container spacemacs-u24, image spacemacs-u24:latest (sha256:bf3b88533029, 1.18 GB). It restarts by itself after a reboot.
  • /work is /opt/spacemacs-dev/repos on the box: verl, vllm, Megatron-LM, transformers.
  • Nothing is installed or compiled when it starts. It was tested with the network switched off.
  • First time you open a Python file in a repo, lsp-mode asks "Select action": press i. If it asks again after go-to-definition lands in a library file, press d.
  • JSON: , = = pretty-print, , = s sorted keys, , = m minify, , T h tree view.
  • Your other containers on the box and the live Spacemacs on the Mac were not touched.

The boundary

Spacemacs Dockerfile owns the editor

docker/spacemacs-u24/Dockerfile

  • Emacs, Spacemacs, all packages and their native code, your config.
  • The language servers and every tool the editor calls: basedpyright, ruff, rg, fd, jq, aspell.
  • Pinned versions, and checks that fail the build.
  • Its contract: one folder /opt/spacemacs, one command /opt/spacemacs/bin/emacs, for Ubuntu 24.04 x86_64.

The verl Dockerfile only composes

docker/verl-spacemacs/Dockerfile

FROM verlai/verl:uv.cu130.dev5
COPY --from=spacemacs-u24 /opt/spacemacs /opt/spacemacs
ENV PATH=/opt/spacemacs/bin:$PATH
  • No apt packages, no settings, no PATH order rules for the editor.
  • Python, uv, the .venv and git stay verl's business.

How the folder keeps to its side:

  • The launcher puts the editor's tools on PATH for Emacs only. In the verl image's shell, python3 and uv are still verl's, and ruff and rg are not visible at all.
  • The folder's own python3 and uv are in tools/fallback, last on Emacs's PATH. They are used only where the image has none.
  • Nothing is in $HOME: the launcher starts Emacs with --init-directory and SPACEMACSDIR.
  • Repos mounted from a host belong to another user, and git refuses them. The launcher allows them for Emacs (Magit) only; the image's git settings are not changed.

My first version did not keep this line: the verl side needed an apt-get for four tools, a PATH order rule, files in /root and a system git setting. That version is gone.

How it is built

On the box, from the git clone (the build context is the config folder):

cd /opt/spacemacs-dev
sudo docker build -t spacemacs-u24:latest \
  -f src/GitConfig/spacemacs/docker/spacemacs-u24/Dockerfile src/GitConfig/spacemacs
sudo docker build -t verl-spacemacs:latest src/GitConfig/spacemacs/docker/verl-spacemacs
  1. Stage emacs-build compiles Emacs and makes its folder self-contained (about 6 minutes on 8 cores, cached afterwards).
  2. Stage tools-build runs bundle-tools.sh: copies rg, fd, jq and aspell with their libraries out of Ubuntu's packages (18 MB).
  3. Final stage: clean ubuntu:24.04, the two folders above, the launcher, pinned uv + basedpyright + ruff, Spacemacs at the pinned commit, then the config and bake.sh:
    1. install every package (239 installed, 262 s);
    2. start again; fail if anything is still being installed;
    3. native-compile all packages (1723 files, 350 s);
    4. warm start: run a real terminal session so Emacs's own built-in Lisp is compiled too (210 more files, 85 s); a second session must have nothing left to compile and no spell-check error;
    5. self-check: Magit runs as native code, every tool is found, spell-check marks a misspelt line, rg/fd/jq/aspell run.

A change to the config repeats only the bake (about 12 minutes). The container on the box was started with:

sudo docker run -d --name spacemacs-u24 --hostname spacemacs-u24 --restart unless-stopped \
  -v /opt/spacemacs-dev/repos:/work spacemacs-u24:latest sleep infinity

With the verl image

  • verlai/verl:uv.cu130.dev5 is pulled on the box (26.9 GB). verl-spacemacs:latest is that plus the folder (27.9 GB).
  • The verl image has no language server, no ruff, no node. It has Python 3.12, uv 0.11.16, the verl source in /workspace/verl and a 13 GB uv cache.
  • It has no venv and no torch until first use, by design. From its own docker/Dockerfile.uv.cu130: "bakes NO fixed .venv ... uv run --extra ... installs the requested extras into /workspace/verl/.venv from the baked cache (fast / offline, no network)". Checked on the box with the network off: 
    cd /workspace/verl
uv run --frozen --offline --all-packages --extra vllm --extra fsdp python3 -c "import torch; print(torch.__version__)"
# 14 s, 257 packages, prints 2.13.0+cu130
  • Once .venv exists, basedpyright uses it by itself (the config looks for .venv in the project), so torch imports resolve in the editor.
  • I read the documentation shipped in the image. I did not search verl's GitHub issues.

Open points

  • vllm diagnostics: none within 90 s, cause not found.
  • x86_64 only as built. The Dockerfile has arm64 paths but that build was not run.
  • The images exist only on the Tokyo box; not pushed to a registry.
  • The folder still expects two things from the image it is copied into: git (for Magit), and binutils if you install more packages and want them native-compiled. The verl image has both.

The files

docker/spacemacs-u24/Dockerfile

# syntax=docker/dockerfile:1
#
# spacemacs-u24: Spacemacs as one self-contained folder, on Ubuntu 24.04.
#
# Everything the editor needs is under /opt/spacemacs and is made at build time:
#
#   /opt/spacemacs/bin/emacs     launcher (the only thing to put on PATH)
#   /opt/spacemacs/emacs         Emacs 30 (terminal build, native compilation),
#                                with the shared libraries it needs in lib/
#   /opt/spacemacs/tools         basedpyright, ruff, rg, fd, jq, aspell;
#                                fallback/ holds uv and a python3 used only when
#                                the surrounding image has none
#   /opt/spacemacs/emacs.d       Spacemacs (develop), every package installed
#                                and native-compiled (bake.sh)
#   /opt/spacemacs/spacemacs.d   the config from this repo
#
# Nothing is downloaded when a container starts and nothing lives in $HOME.
#
# Use it in another Ubuntu 24.04 image (same Ubuntu as verlai/verl:uv.cu130.dev5)
# with two lines; that image only needs git:
#   COPY --from=spacemacs-u24:latest /opt/spacemacs /opt/spacemacs
#   ENV PATH=/opt/spacemacs/bin:$PATH
#
# The build context is the spacemacs/ directory (the config), not this folder:
#   docker build -t spacemacs-u24 -f docker/spacemacs-u24/Dockerfile .
ARG UBUNTU=24.04

# ---------------------------------------------------------------- build Emacs
FROM ubuntu:${UBUNTU} AS emacs-build
ARG EMACS_VERSION=30.2
ARG DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      ca-certificates curl xz-utils build-essential pkg-config texinfo patchelf \
      libgccjit-13-dev libgnutls28-dev libncurses-dev libtree-sitter-dev \
      libsqlite3-dev zlib1g-dev
RUN curl -fsSL https://ftpmirror.gnu.org/emacs/emacs-${EMACS_VERSION}.tar.xz | tar -xJ -C /tmp
WORKDIR /tmp/emacs-${EMACS_VERSION}
# Terminal only (no X, no image libraries, no libxml2: it drags in 35 MB of ICU
# and is only used by the built-in web browser). Native compilation is on; Lisp is
# compiled to native code at build time by bake.sh, into
# ~/.emacs.d/eln-cache.
RUN ./configure --prefix=/opt/spacemacs/emacs \
      --with-native-compilation --with-tree-sitter --with-gnutls --without-xml2 \
      --with-sqlite3 --with-modules --with-zlib \
      --without-x --without-sound --without-dbus --without-gsettings \
      --without-selinux --without-gpm --without-pop --without-mailutils \
      CFLAGS="-O2 -g0" \
 && make -j"$(nproc)" && make install-strip
# Make the tree self-contained: copy every non-glibc shared library Emacs links
# against next to it and point the binary there, so /opt/spacemacs/emacs runs in
# any Ubuntu 24.04 container without installing packages.
RUN set -eux; cd /opt/spacemacs/emacs; mkdir -p lib; \
    bin=$(readlink -f bin/emacs); \
    ldd "$bin" | awk '$3 ~ /^\// {print $3}' \
      | grep -Ev '/(libc|libm|libdl|libpthread|librt|libresolv|ld-linux[^/]*)\.so' \
      | xargs -I{} cp -L {} lib/; \
    for l in lib/libgccjit.so.0; do ldd "$l" | awk '$3 ~ /^\// {print $3}' \
      | grep -Ev '/(libc|libm|libdl|libpthread|librt|libresolv|ld-linux[^/]*)\.so' \
      | xargs -I{} cp -Ln {} lib/; done; \
    patchelf --set-rpath '$ORIGIN/../lib' "$bin"; \
    for l in lib/*.so*; do patchelf --set-rpath '$ORIGIN' "$l"; done; \
    g=/usr/lib/gcc/x86_64-linux-gnu/13; a=/usr/lib/x86_64-linux-gnu; [ -d "$g" ] || { g=/usr/lib/gcc/aarch64-linux-gnu/13; a=/usr/lib/aarch64-linux-gnu; }; \
    mkdir -p lib/gcc; cp -L "$g"/crtbeginS.o "$g"/crtendS.o "$g"/libgcc.a "$g"/libgcc_s.so "$a"/crti.o "$a"/crtn.o "$a"/libc_nonshared.a lib/gcc/; \
    sed "s#$a/libc_nonshared.a#/opt/spacemacs/emacs/lib/gcc/libc_nonshared.a#" "$a"/libc.so > lib/gcc/libc.so; cat lib/gcc/libc.so; \
    printf '%s\n' ';; The native compiler links each .eln with these GCC start files and libgcc,' \
      ';; bundled here so that only binutils (as, ld) is needed at run time.' \
      '(setq native-comp-driver-options (list "-B/opt/spacemacs/emacs/lib/gcc/"))' \
      > share/emacs/site-lisp/site-start.el; \
    rm -rf share/man share/info share/icons share/applications share/metainfo include; \
    find share/emacs -name '*.el.gz' -path '*/leim/*' -delete || true; \
    ./bin/emacs --batch --eval '(princ (format "%s native=%s json=%s treesit=%s\n" emacs-version (native-comp-available-p) (fboundp (quote json-parse-string)) (treesit-available-p)))'

# ---------------------------------------------------------------- bundle tools
# rg, fd, jq and aspell copied out of Ubuntu's packages into the folder, with
# their libraries, so the folder does not depend on apt packages elsewhere.
FROM ubuntu:${UBUNTU} AS tools-build
ARG DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      ripgrep fd-find jq aspell aspell-en patchelf
COPY docker/spacemacs-u24/build/bundle-tools.sh /tmp/bundle-tools.sh
RUN bash /tmp/bundle-tools.sh /opt/spacemacs/tools

# ---------------------------------------------------------------- final image
FROM ubuntu:${UBUNTU}
ARG DEBIAN_FRONTEND=noninteractive
# For this stand-alone image only (none of it is needed inside /opt/spacemacs):
# git for Magit and the Spacemacs download, curl/gnupg for package downloads at
# build time, binutils for the native compiler, tmux/less/ssh for comfort.
RUN apt-get update && apt-get install -y --no-install-recommends \
      ca-certificates git curl gnupg openssh-client less tmux binutils \
 && rm -rf /var/lib/apt/lists/* /usr/share/doc/* /usr/share/man/*

COPY --from=emacs-build /opt/spacemacs/emacs /opt/spacemacs/emacs
COPY --from=tools-build /opt/spacemacs/tools /opt/spacemacs/tools
COPY --chmod=755 docker/spacemacs-u24/build/emacs-launcher.sh /opt/spacemacs/bin/emacs
RUN ln -s ../emacs/bin/emacsclient /opt/spacemacs/bin/emacsclient

ENV LANG=C.UTF-8 LC_ALL=C.UTF-8 TERM=xterm-256color COLORTERM=truecolor \
    PATH=/opt/spacemacs/bin:$PATH
RUN printf 'export PATH=/opt/spacemacs/bin:$PATH\n' > /etc/profile.d/10-spacemacs.sh

# Language servers, pinned, installed by uv together with the standalone Python
# they run on. basedpyright brings its own node. uv itself and a python3 link go
# to tools/fallback, which the launcher puts last on PATH.
ARG UV_VERSION=0.13.8
ARG BASEDPYRIGHT_VERSION=1.40.2
ARG RUFF_VERSION=0.17.5
RUN set -eux; t=/opt/spacemacs/tools; mkdir -p $t/fallback; \
    export UV_UNMANAGED_INSTALL=$t/fallback; \
    curl -LsSf https://astral.sh/uv/${UV_VERSION}/install.sh | sh; \
    export PATH=$t/fallback:$t/bin:$PATH UV_TOOL_DIR=$t/uv UV_TOOL_BIN_DIR=$t/bin \
           UV_PYTHON_INSTALL_DIR=$t/python UV_NO_CACHE=1; \
    uv tool install basedpyright==${BASEDPYRIGHT_VERSION}; uv tool install ruff==${RUFF_VERSION}; \
    # the standalone Python only has to run basedpyright's small launcher: drop
    # its test suite, Tk, IDLE, headers and static libraries
    py=$(readlink -f $t/python/cpython-*-gnu | head -1); test -d "$py/lib"; \
    rm -rf "$py"/lib/python3*/test "$py"/lib/python3*/idlelib "$py"/lib/python3*/tkinter \
           "$py"/lib/python3*/turtledemo "$py"/lib/python3*/ensurepip "$py"/lib/python3*/config-* \
           "$py"/lib/tcl* "$py"/lib/tk* "$py"/lib/itcl* "$py"/lib/thread* "$py"/lib/*.a \
           "$py"/include "$py"/share; \
    find $t -name __pycache__ -prune -exec rm -rf {} +; \
    ln -s "$py/bin/python3" $t/fallback/python3; ln -s python3 $t/fallback/python; \
    basedpyright --version; ruff --version; $t/fallback/python3 --version; du -sh $t/*

# Spacemacs itself, pinned to the commit the config was developed against.
ARG SPACEMACS_REF=88393ec346620f8794348798ab28f8bdf562b767
RUN set -eux; git init -q /opt/spacemacs/emacs.d; cd /opt/spacemacs/emacs.d; \
    git remote add origin https://github.com/syl20bnr/spacemacs; \
    git fetch -q --depth 1 origin "$SPACEMACS_REF"; git checkout -q -B develop FETCH_HEAD; \

docker/spacemacs-u24/build/emacs-launcher.sh

#!/bin/sh
# /opt/spacemacs/bin/emacs - Spacemacs launcher.
# Everything lives under /opt/spacemacs; nothing is read from or written to $HOME.
#  - the editor's tools (ruff, basedpyright, rg, fd, jq, aspell) go on PATH for
#    Emacs only, so they never change what the surrounding image runs;
#  - python3 and uv from here go last: the image's own (or a project venv) win;
#  - repos mounted from a host belong to another user: allow git (Magit) to open
#    them, for Emacs only.
S=/opt/spacemacs
export SPACEMACSDIR=$S/spacemacs.d/
export PATH=$S/tools/bin:$PATH:$S/tools/fallback
export GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0='*'
exec $S/emacs/bin/emacs --init-directory=$S/emacs.d "$@"

docker/spacemacs-u24/build/bake.sh

#!/usr/bin/env bash
# bake.sh - make Spacemacs ready to use with no network at start-up.
# Run by the Dockerfile (and by hand in a scratch container while developing).
# Needs the final layout: /opt/spacemacs/{bin/emacs,emacs.d,spacemacs.d}. Native
# code is tied to the path it was compiled at, so bake where it will be used.
#   1. install every package the config asks for
#   2. run again and fail if anything is still being installed
#   3. native-compile all packages now, so Emacs does not do it at first use
#   4. run a real session so Emacs' own built-in Lisp is compiled too
#   5. check the result: native code in use, every tool works, spell-check works
set -euo pipefail
S=/opt/spacemacs
here=$(cd "$(dirname "$0")" && pwd)
ln -sfn init.linux.el "$S/spacemacs.d/init.el"

echo "== 4. warm start"; t=$SECONDS
# Emacs compiles its own built-in Lisp the first time a session loads it. Run a
# real terminal session now, open the usual kinds of file, and wait until the
# background compiler is idle; then a second session must find nothing to do.
ec() { "$S/emacs/bin/emacsclient" -s bake --eval "$1" 2>/dev/null; }
warm() {
  TERM=xterm-256color "$S/tools/fallback/python3" -c 'import pty,sys; pty.spawn(sys.argv[1:])' \
    sh -c "stty rows 50 cols 200; exec $S/bin/emacs -nw --eval '(progn (setq server-name \"bake\") (server-start))'" \
    </dev/null >/dev/null 2>&1 &
  for _ in $(seq 1 600); do ec t >/dev/null && break; sleep 0.2; done
  ec "$1" >/dev/null || true
  for _ in $(seq 1 300); do
    [ "$(ec '(and (null comp-files-queue) (zerop (comp--async-runnings)))')" = t ] && break; sleep 2
  done
  queued=$(ec '(length comp-files-queue)' || echo unknown)
  flyspell_error=$(ec '(with-current-buffer "*Messages*" (save-excursion (goto-char (point-min)) (if (search-forward "Error enabling Flyspell" nil t) 1 0)))' || echo unknown)
  ec '(kill-emacs)' >/dev/null || true; wait || true
}
w=$(mktemp -d); printf 'import os\nx = 1\n' >"$w/w.py"; printf '{"a":1}\n' >"$w/w.json"
printf '# t\n' >"$w/w.md"; printf '(message "t")\n' >"$w/w.el"; printf 'helo wrld\n' >"$w/w.txt"
warm "(progn (dolist (f '(\"w.py\" \"w.json\" \"w.md\" \"w.el\" \"w.txt\")) (find-file (expand-file-name f \"$w\"))) (dolist (p '(magit lsp-mode lsp-ui company helm flycheck)) (require p)) (dired \"$w\") t)"
warm t
echo "   second session: $queued files left to compile, flyspell error: $flyspell_error, $((SECONDS-t)) s"
[ "$queued" = 0 ] && [ "$flyspell_error" = 0 ] || { echo "warm start check failed"; exit 1; }
rm -rf "$w"
echo "   $(find "$S/emacs.d/eln-cache" -name '*.eln' | wc -l) .eln files now"

echo "== 5. self-check"
"${boot[@]}" --eval "(progn (require 'magit) (unless (subr-native-elisp-p (symbol-function 'magit-status)) (error \"magit is not native-compiled\")) (dolist (p '(\"ruff\" \"basedpyright-langserver\" \"rg\" \"fd\" \"jq\" \"aspell\" \"python3\")) (unless (executable-find p) (error \"missing tool %s\" p))) (with-temp-buffer (text-mode) (insert \"helo wrld\") (flyspell-mode 1) (flyspell-buffer) (unless (seq-some (lambda (o) (overlay-get o 'flyspell-overlay)) (overlays-in (point-min) (point-max))) (error \"spell-check found nothing in a misspelt line\"))) (princ \"   self-check ok\n\"))" </dev/null 2>"$log/check.log" | grep "self-check ok"
for tool in rg fd jq; do "$S/tools/bin/$tool" --version >/dev/null; done
echo helo | "$S/tools/bin/aspell" -a 2>&1 | grep -q '^& helo' 
! echo helo | "$S/tools/bin/aspell" -a 2>&1 | grep -qi 'warning\|error'
# The native-compile workers are plain child Emacs processes and may leave an
# empty ~/.emacs.d/snippets behind. Remove empty leftovers; real files are an error.
[ ! -d "$HOME/.emacs.d" ] || find "$HOME/.emacs.d" -depth -type d -empty -delete
[ ! -e "$HOME/.emacs.d" ] || { echo "something wrote to ~/.emacs.d:"; find "$HOME/.emacs.d" | head; exit 1; }
du -sh "$S" "$S"/*

#!/usr/bin/env bash
# bundle-tools.sh - copy rg, fd, jq and aspell (with its English dictionary) out
# of Ubuntu's packages into one relocatable folder, so the editor does not
# depend on apt packages being installed in the image it is copied into.
#   bundle-tools.sh /opt/spacemacs/tools
# Needs: apt packages ripgrep fd-find jq aspell aspell-en patchelf.
set -euo pipefail
dst=$1; mkdir -p "$dst"/{bin,lib,libexec,share/aspell}
libs_of() { ldd "$1" | awk '$3 ~ /^\// {print $3}' \
  | grep -Ev '/(libc|libm|libdl|libpthread|librt|libresolv|libgcc_s|libstdc\+\+|ld-linux[^/]*)\.so' || true; }
put() { # put <binary> <dest dir> <name>: copy it, copy its libraries, point it at them
  cp -L "$1" "$2/$3"
  for l in $(libs_of "$1"); do cp -Ln "$l" "$dst/lib/"; done
  patchelf --set-rpath "$dst/lib" "$2/$3"; }
put /usr/bin/rg     "$dst/bin" rg
put /usr/bin/fdfind "$dst/bin" fd
put /usr/bin/jq     "$dst/bin" jq
put /usr/bin/aspell "$dst/libexec" aspell
for l in "$dst"/lib/*.so*; do patchelf --set-rpath "$dst/lib" "$l"; done
# aspell looks for its data in fixed /usr paths: keep data and dictionaries
# together here and tell it where they are.
cp -rL /usr/lib/aspell/. /var/lib/aspell/. "$dst/share/aspell/"
# Its filter modules (*.amf, *-filter.so) are in an arch-named sub-folder.
filters=$(cd "$dst/share/aspell" && ls -d */ | head -1)
printf '#!/bin/sh\nexec %s/libexec/aspell --data-dir=%s/share/aspell --dict-dir=%s/share/aspell --filter-path=%s/share/aspell/%s "$@"\n' \
  "$dst" "$dst" "$dst" "$dst" "${filters%/}" > "$dst/bin/aspell"
chmod +x "$dst/bin/aspell"
ls "$dst/bin" "$dst/lib"; du -sh "$dst"
