spacemacs-u24: dev notes

13 November 2026. A Spacemacs image on Ubuntu 24.04, built on the Tokyo box, with a container running there for you to try. This page says what was asked, what was built, how it was checked, and where every file and log is.

Try it

tokyo            # on the Mac: opens the SSM session to the Tokyo box
smx emacs        # Emacs inside the container, in /work
smx              # or a shell in the container; then type: emacs
  • Container spacemacs-u24, image spacemacs-u24:latest (sha256:bdacf09ede01, 1.16 GB). It restarts by itself after a reboot.
  • /work in the container is /opt/spacemacs-dev/repos on the box: verl, vllm, Megatron-LM, transformers (shallow clones made for this test).
  • Nothing is installed when it starts. Packages, native code and your config are inside the image. It was tested with the network switched off.
  • First time you open a Python file in a repo, lsp-mode asks "Select action": press i (import the project root). If go-to-definition lands in a library stub and it asks again, press d (do not ask again). This is the same behaviour as in your config on the Mac.
  • JSON: , = = pretty-print, , = s pretty-print with sorted keys, , = m minify, , T h tree view. No node and no language server are needed for JSON.
  • Your other containers on the box (dev-tokyo, sgdev, cc-*) were not touched. The live Spacemacs on the Mac was not touched.

How it was built

Build command, run on the box in /opt/spacemacs-dev (the build context is the config folder):

sudo docker build -t spacemacs-u24:latest \
  -f GitConfig/spacemacs/docker/ubuntu24/Dockerfile GitConfig/spacemacs
  1. Stage 1 compiles Emacs 30.2 and makes the folder self-contained (about 10 minutes, cached after the first time).
  2. Stage 2 starts from a clean ubuntu:24.04, adds the apt tools, copies Emacs in, installs uv, basedpyright and ruff, and fetches Spacemacs at the pinned commit.
  3. The config is copied in and docker/ubuntu24/bake.sh runs:
    • start Emacs in batch mode, which installs every package (239 installed, 399 s);
    • start again and fail the build if anything is still being installed (nothing was);
    • native-compile all packages with native-compile-all.el (1723 files, 355 s on 8 cores).

Run command used for your container:

sudo docker run -d --name spacemacs-u24 --hostname spacemacs-u24 --restart unless-stopped \
  -v /opt/spacemacs-dev/repos:/work spacemacs-u24:latest sleep infinity

docker/ubuntu24/run.sh does the same on any machine (REPOS=/path DOCKER="sudo docker" docker/ubuntu24/run.sh). With LIVE_CONFIG=1 it mounts the repo's config over the baked one, so you can edit the config without rebuilding.

Problems and fixes

Builds 1 and 2: native compilation failed in the final image (ld: cannot find crtbeginS.o, -lgcc, -lc). The copied libgccjit could not find GCC's link files.Bundle those files in /opt/spacemacs/emacs/lib/gcc and set native-comp-driver-options in site-start.el. Build 3 passed.
First test: python3 not found; git said "dubious ownership" on the mounted repos, so Magit failed.Link uv's Python as python3; git config --system safe.directory '*'. Builds 5 and 6.
Build 5 failed, and the Python trim in build 4 did nothing: uv keeps two names for its Python folder and my shell variable held both.Resolve the real folder with readlink -f and check it exists.
Packages were installed at first start into a volume, not in the image.You asked for a self-contained image. bake.sh now runs at build time; the volume is gone. Build 7.
About 2.5 hours lost on my side: a poll script had a grep with no file name, which waits for input for ever.Fixed the script. No effect on the image.
Test driver errors: a vllm file path that does not exist in current vllm (the driver created an empty file there; removed, git status in vllm is clean), and an unanswered lsp "Select action" question that stopped one run.Driver now checks the file exists and answers the question in advance.

Use with the verl image

Not tested yet (the verl image is a 12 GB download; I did not pull it). The design is that the three folders can be copied into any Ubuntu 24.04 image, for example in a Dockerfile:

FROM verlai/verl:uv.cu130.dev5
COPY --from=spacemacs-u24:latest /opt/spacemacs   /opt/spacemacs
COPY --from=spacemacs-u24:latest /root/.emacs.d   /root/.emacs.d
COPY --from=spacemacs-u24:latest /root/.spacemacs.d /root/.spacemacs.d
ENV PATH=/opt/spacemacs/emacs/bin:/opt/spacemacs/tools/bin:$PATH

What supports this: Emacs carries its own libraries, and both images use Ubuntu 24.04's glibc. What could still differ: the home directory must be /root (native code file names depend on the path), and the apt tools (ripgrep, fd-find, jq, aspell, binutils) must be in the verl image or installed there.

Open points

  • Mounting into the real verl image is not tested (see above).
  • The image is x86_64 only as built. The Dockerfile has the arm64 paths but that build was not run.
  • The image exists only on the Tokyo box. It is not pushed to a registry.
  • The repos have no Python environment, so basedpyright reports third-party imports (torch and others) as unresolved. Create one with uv venv in a repo, or work inside the verl image.
  • A config change means a rebuild of the last step (about 13 minutes), or use LIVE_CONFIG=1.

Dockerfile

spacemacs/docker/ubuntu24/Dockerfile

# syntax=docker/dockerfile:1
#
# spacemacs-u24: a small, portable Spacemacs image on Ubuntu 24.04.
#
# Same Ubuntu as verlai/verl:uv.cu130.dev5 (nvidia/cuda 13.0.2 on ubuntu24.04),
# so the same glibc: project venvs built in that image resolve here, and the
# two directories this image produces can be mounted into that image as is.
#
#   /opt/spacemacs/emacs   Emacs 30 (terminal build, native compilation), with
#                          the shared libraries it needs bundled in lib/
#   /opt/spacemacs/tools   uv, basedpyright, ruff and the Python they run on
#   /root/.emacs.d         Spacemacs (develop) with every package installed and
#                          native-compiled at build time (bake.sh)
#   /root/.spacemacs.d     the config from this repo, copied in
#
# Nothing is downloaded when a container starts: `docker run -it spacemacs-u24 emacs`
# works with the network off.
#
# The build context is the spacemacs/ directory (the config), not this folder:
#   docker build -t spacemacs-u24 -f docker/ubuntu24/Dockerfile .
ARG UBUNTU=24.04

# ---------------------------------------------------------------- build Emacs
FROM ubuntu:${UBUNTU} AS emacs-build
ARG EMACS_VERSION=30.2
ARG DEBIAN_FRONTEND=noninteractive
RUN apt-get update && apt-get install -y --no-install-recommends \
      ca-certificates curl xz-utils build-essential pkg-config texinfo patchelf \
      libgccjit-13-dev libgnutls28-dev libncurses-dev libtree-sitter-dev \
      libsqlite3-dev zlib1g-dev
RUN curl -fsSL https://ftpmirror.gnu.org/emacs/emacs-${EMACS_VERSION}.tar.xz | tar -xJ -C /tmp
WORKDIR /tmp/emacs-${EMACS_VERSION}
# Terminal only (no X, no image libraries, no libxml2: it drags in 35 MB of ICU
# and is only used by the built-in web browser). Native compilation is on; Lisp is
# compiled to native code at build time by bake.sh, into
# ~/.emacs.d/eln-cache.
RUN ./configure --prefix=/opt/spacemacs/emacs \
      --with-native-compilation --with-tree-sitter --with-gnutls --without-xml2 \
      --with-sqlite3 --with-modules --with-zlib \
      --without-x --without-sound --without-dbus --without-gsettings \
      --without-selinux --without-gpm --without-pop --without-mailutils \
      CFLAGS="-O2 -g0" \
 && make -j"$(nproc)" && make install-strip
# Make the tree self-contained: copy every non-glibc shared library Emacs links
# against next to it and point the binary there, so /opt/spacemacs/emacs runs in
# any Ubuntu 24.04 container without installing packages.
RUN set -eux; cd /opt/spacemacs/emacs; mkdir -p lib; \
    bin=$(readlink -f bin/emacs); \
    ldd "$bin" | awk '$3 ~ /^\// {print $3}' \
      | grep -Ev '/(libc|libm|libdl|libpthread|librt|libresolv|ld-linux[^/]*)\.so' \
      | xargs -I{} cp -L {} lib/; \
    for l in lib/libgccjit.so.0; do ldd "$l" | awk '$3 ~ /^\// {print $3}' \
      | grep -Ev '/(libc|libm|libdl|libpthread|librt|libresolv|ld-linux[^/]*)\.so' \
      | xargs -I{} cp -Ln {} lib/; done; \
    patchelf --set-rpath '$ORIGIN/../lib' "$bin"; \
    for l in lib/*.so*; do patchelf --set-rpath '$ORIGIN' "$l"; done; \
    g=/usr/lib/gcc/x86_64-linux-gnu/13; a=/usr/lib/x86_64-linux-gnu; [ -d "$g" ] || { g=/usr/lib/gcc/aarch64-linux-gnu/13; a=/usr/lib/aarch64-linux-gnu; }; \
    mkdir -p lib/gcc; cp -L "$g"/crtbeginS.o "$g"/crtendS.o "$g"/libgcc.a "$g"/libgcc_s.so "$a"/crti.o "$a"/crtn.o "$a"/libc_nonshared.a lib/gcc/; \
    sed "s#$a/libc_nonshared.a#/opt/spacemacs/emacs/lib/gcc/libc_nonshared.a#" "$a"/libc.so > lib/gcc/libc.so; cat lib/gcc/libc.so; \
    printf '%s\n' ';; The native compiler links each .eln with these GCC start files and libgcc,' \
      ';; bundled here so that only binutils (as, ld) is needed at run time.' \
      '(setq native-comp-driver-options (list "-B/opt/spacemacs/emacs/lib/gcc/"))' \
      > share/emacs/site-lisp/site-start.el; \
    rm -rf share/man share/info share/icons share/applications share/metainfo include; \
    find share/emacs -name '*.el.gz' -path '*/leim/*' -delete || true; \
    ./bin/emacs --batch --eval '(princ (format "%s native=%s json=%s treesit=%s\n" emacs-version (native-comp-available-p) (fboundp (quote json-parse-string)) (treesit-available-p)))'

# ---------------------------------------------------------------- final image
FROM ubuntu:${UBUNTU}
ARG DEBIAN_FRONTEND=noninteractive
# git/curl/gnupg: Spacemacs and package downloads.  ripgrep/fd: SPC / and SPC p f.
# jq: JSON syntax check (flycheck).  aspell: spell-checking layer.
# binutils: the assembler and linker libgccjit calls to turn Lisp into native
# code at run time. Everything else it needs is bundled in /opt/spacemacs/emacs.
RUN apt-get update && apt-get install -y --no-install-recommends \
      ca-certificates git curl gnupg openssh-client less tmux \
      ripgrep fd-find jq aspell aspell-en \
      binutils \
 && ln -s /usr/bin/fdfind /usr/local/bin/fd \
 && rm -rf /var/lib/apt/lists/* /usr/share/doc/* /usr/share/man/*

COPY --from=emacs-build /opt/spacemacs/emacs /opt/spacemacs/emacs

ENV LANG=C.UTF-8 LC_ALL=C.UTF-8 TERM=xterm-256color COLORTERM=truecolor \
    PATH=/opt/spacemacs/emacs/bin:/opt/spacemacs/tools/bin:/root/.local/bin:/root/.cargo/bin:$PATH
RUN printf 'export PATH=/opt/spacemacs/emacs/bin:/opt/spacemacs/tools/bin:$HOME/.local/bin:$HOME/.cargo/bin:$PATH\n' \
      > /etc/profile.d/10-spacemacs.sh

# uv installs the language servers into /opt/spacemacs/tools, together with the
# standalone Python they run on. basedpyright brings its own node.
RUN set -eux; export UV_UNMANAGED_INSTALL=/opt/spacemacs/tools/bin; \
    curl -LsSf https://astral.sh/uv/install.sh | sh; \
    export UV_TOOL_DIR=/opt/spacemacs/tools/uv UV_TOOL_BIN_DIR=/opt/spacemacs/tools/bin \
           UV_PYTHON_INSTALL_DIR=/opt/spacemacs/tools/python UV_NO_CACHE=1; \
    uv tool install basedpyright; uv tool install ruff; \
    # the standalone Python only has to run basedpyright's small launcher: drop
    # its test suite, Tk, IDLE, headers and static libraries (about 70 MB)
    py=$(readlink -f /opt/spacemacs/tools/python/cpython-*-gnu | head -1); test -d "$py/lib"; \
    rm -rf "$py"/lib/python3*/test "$py"/lib/python3*/idlelib "$py"/lib/python3*/tkinter \
           "$py"/lib/python3*/turtledemo "$py"/lib/python3*/ensurepip "$py"/lib/python3*/config-* \
           "$py"/lib/tcl* "$py"/lib/tk* "$py"/lib/itcl* "$py"/lib/thread* "$py"/lib/*.a \
           "$py"/include "$py"/share; \
    find /opt/spacemacs/tools -name __pycache__ -prune -exec rm -rf {} +; \
    basedpyright --version; ruff --version; du -sh /opt/spacemacs/tools/*

# Emacs' Python layer runs "python3" for small helper scripts, and Ubuntu's
# minimal image has none. Reuse the interpreter uv already installed (no extra
# size); a project venv earlier on PATH still wins.
# Mounted repos belong to a host user, not to root: tell git to accept them,
# otherwise Magit fails with "dubious ownership".
RUN set -eux; py=$(readlink -f /opt/spacemacs/tools/python/cpython-*-gnu | head -1); test -d "$py/lib"; \
    ln -s "$py/bin/python3" /opt/spacemacs/tools/bin/python3; \
    ln -s python3 /opt/spacemacs/tools/bin/python; \
    python3 -c 'import sys, json, ast; print("python3", sys.version.split()[0])'; \
    git config --system --add safe.directory '*'

# Spacemacs itself, pinned to the commit the config was developed against.
ARG SPACEMACS_REF=88393ec346620f8794348798ab28f8bdf562b767
RUN set -eux; git init -q /root/.emacs.d; cd /root/.emacs.d; \
    git remote add origin https://github.com/syl20bnr/spacemacs; \
    git fetch -q --depth 1 origin "$SPACEMACS_REF"; git checkout -q -B develop FETCH_HEAD; \
    git gc -q --prune=now

# Prove native compilation works with only the runtime pieces above.
RUN emacs --batch --eval '(progn (require (quote comp)) (let ((f "/tmp/t.el")) (with-temp-file f (insert ";;; -*- lexical-binding: t -*-\n(defun t-add (a b) (+ a b))\n")) (princ (format "native-compiled: %s\n" (native-compile f)))))' \
 && rm -rf /tmp/* /root/.emacs.d/eln-cache

# The config, then everything it asks for: bake.sh installs all packages, checks
# a second start installs nothing, and native-compiles the packages. Logs stay in
# /var/log/spacemacs-bake. The same script was developed by hand in a container.
COPY . /root/.spacemacs.d
RUN BAKE_LOG=/var/log/spacemacs-bake bash /root/.spacemacs.d/docker/ubuntu24/bake.sh \
 && rm -rf /tmp/* /root/.cache

WORKDIR /work
CMD ["bash", "-l"]

bake.sh

#!/usr/bin/env bash
# bake.sh - make Spacemacs ready to use with no network at start-up.
# Run by the Dockerfile (and by hand in a scratch container while developing).
# Needs: Emacs on PATH, Spacemacs in ~/.emacs.d, the config in ~/.spacemacs.d.
#   1. install every package the config asks for
#   2. run again and fail if anything is still being installed
#   3. native-compile all packages now, so Emacs does not do it at first use
set -euo pipefail
cd "$HOME"
here=$(cd "$(dirname "$0")" && pwd)
ln -sfn init.linux.el "$HOME/.spacemacs.d/init.el"
boot=(emacs --batch -l "$HOME/.emacs.d/early-init.el" -l "$HOME/.emacs.d/init.el"
      --eval "(run-hooks 'emacs-startup-hook)")
log=${BAKE_LOG:-/tmp/bake}; mkdir -p "$log"

echo "== 1. install packages"; t=$SECONDS
"${boot[@]}" </dev/null >"$log/install.log" 2>&1
echo "   $(grep -c 'installing package' "$log/install.log") installed in $((SECONDS-t)) s"

echo "== 2. second start must install nothing"; t=$SECONDS
"${boot[@]}" </dev/null >"$log/second.log" 2>&1
if grep -q 'installing package' "$log/second.log"; then
  grep 'installing package' "$log/second.log" | head; echo "packages still missing"; exit 1
fi
echo "   ok in $((SECONDS-t)) s, $(ls "$HOME"/.emacs.d/elpa/*/develop | grep -vc archives) package dirs"

echo "== 3. native-compile"; t=$SECONDS
"${boot[@]}" -l "$here/native-compile-all.el" </dev/null >"$log/native.log" 2>&1
tail -1 "$log/native.log"
echo "   $(find "$HOME/.emacs.d/eln-cache" -name '*.eln' | wc -l) .eln files in $((SECONDS-t)) s"
du -sh "$HOME/.emacs.d" "$HOME/.emacs.d/elpa" "$HOME/.emacs.d/eln-cache"

native-compile-all.el

;;; native-compile-all.el --- compile every installed package ahead of time  -*- lexical-binding: t -*-
;; Loaded by bake.sh after Spacemacs has started in batch mode. Without this,
;; Emacs compiles each package in the background the first time it is used.
(require 'comp)
(setq native-comp-async-jobs-number (max 1 (num-processors))
      native-comp-async-report-warnings-errors 'silent)
(native-compile-async (list package-user-dir) 'recursively)
(let ((running (if (fboundp 'comp--async-runnings) #'comp--async-runnings #'comp-async-runnings))
      (start (float-time)))
  (while (or comp-files-queue (> (funcall running) 0))
    (accept-process-output nil 2))
  (message "native-compile-all: done in %d s" (- (float-time) start)))
