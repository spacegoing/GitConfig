2. Why it froze on big repos

None of these is a single bug; each is Emacs doing synchronous work that scales with repository or file size. On vllm / verl / Megatron they add up to a frozen frame.

3. Plan and design decisions

One dotfile, every machine

init.el is a real file generated from the Spacemacs template that matches the installed version, with your real settings merged in (the diff between template and your files was small: theme, font, line numbers, layers, user code). Machine differences are handled inside it (system-type checks, "pick the elpa layout that exists") or in an untracked local.el.

Python: basedpyright + ruff server

Pyright-family servers are incremental, out-of-process and handle vllm-sized trees in "open files only" mode. basedpyright is the pip-installable build with node bundled, so one install script works on the Mac and in the Linux container (no npm). ruff server is ruff's own LSP (stable since 0.5) and replaces both the deprecated ruff-lsp wrapper and the python-lsp-ruff plugin. lsp-mode runs ruff as an add-on next to basedpyright: lint and formatting from ruff, everything else from basedpyright. Type checking is "off" by default so diagnostics look like your ruff-only pylsp did; one variable raises it.

Rust: rust-analyzer

The rust layer already selects lsp when the lsp layer is present and rust-analyzer is installed via rustup. The config now says so explicitly and tells rust-analyzer to watch files itself, since Emacs-side watching is off.

Habits first

Every key, face and behaviour you had was listed before changing anything (see section 6). Where a mechanism had to go (semantic), the key you press (, p, SPC j M) still does the same job through a different engine.

Safe to try, safe to undo

dotspacemacs-install-packages is used-but-keep-unused, so switching between branches never uninstalls packages. Every change is one commit. Rolling back is git checkout master.

Tested, not assumed

Nothing was evaluated in your running Emacs. ~/.emacs.d was cloned (APFS clone, cache wiped) into a scratch HOME, and the branch was started there in batch mode and as a real Emacs.app window.

6. How to adopt it

  1. Revoke the token on GitHub (Settings → Developer settings → Personal access tokens). It has been public in this repo's history since 2017 regardless of what you do with the branch.
  2. Switch the live config to the branch (the worktree has to be released first, because git allows a branch to be checked out in one place only): 
    cd ~/sg21CodeLab/GitConfig
git worktree remove ~/sg21CodeLab/GitConfig-wt-spacemacs-overhaul
git checkout spacemacs-overhaul        # ~/.spacemacs.d now has the new init.el
    Or keep working on master and fast-forward it: git merge --ff-only spacemacs-overhaul after the worktree is removed.
  3. Install the servers (no conda env is modified; ~1 min): 
    ~/.spacemacs.d/scripts/install-lsp-servers.sh
  4. Start Emacs. First start installs three packages (helm-ctest, evil-mc, cmake-mode). Open a Python file: the mode line shows LSP[pyright:...][ruff-lsp:...]. If a server is missing, SPC m b d describes the session.
  5. Linux box / container: pull the branch, run the same script, optionally copy local.el.example to local.el for machine-specific paths (the /root/.venv/base settings from the old Linux file go there).

Roll back at any time: git checkout master in GitConfig and restart Emacs. Nothing was uninstalled, so the old config starts as before. .spacemacs.env and .spacemacs.env.old stay where they are (now git-ignored).

8. Recommendations not done here

  • Emacs build with native compilation (emacs-plus or emacs-mac). The single biggest remaining speed-up for lsp-mode on this machine.
  • Update Spacemacs and packages (git pull in ~/.emacs.d, then SPC f e U). lsp-mode/lsp-pyright/rustic are from July 2024; newer versions name the ruff client ruff and know basedpyright natively. The config already handles both generations, so the update is optional and can wait until the new setup has settled.
  • ruff settings on the Mac. Your GitConfig/python/.config/ruff/ruff.toml (line-length 65, isort rules) is installed on the Linux boxes but not on this Mac (~/.config/ruff/ does not exist), so ruff uses defaults here unless a project has its own pyproject.toml. Symlink it if you want the same rules everywhere.
  • dired+ is a 2023 single-file package with cl and case deprecation warnings under Emacs 29; it works, but it is the most likely thing to break on a future Emacs upgrade. dired-hide-details-mode plus dired-kill-when-opening-new-dired-buffer cover most of what it is used for here.
  • Snippets: snippets/python-mode duplicates entries from the bundled yasnippet-snippets (yasnippet warns "multiple snippets with same identity"). Deleting the private copies that are identical to the bundled ones removes the warning.
  • Linux check: after pulling the branch on the Tokyo container, run the install script and open a Python file; the only expected difference is local.el for interpreter paths.
